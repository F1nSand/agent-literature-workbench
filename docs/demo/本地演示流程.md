# 本地演示流程

本流程展示当前主产品路径：文献库、格式对应的阅读器、全局助手和独立阅读笔记。演示使用本人有权处理的资料；云端 OCR、Embedding 或 Agent 请求可能发送文献内容并产生费用，建议从少量文件和少量问题开始。当前 B2 仍待主流程浏览器验收，百篇真实语料验收尚未完成。

1. 按[本地部署说明](../operations/本地部署与数据保护.md)启动产品，确认前端可访问且 API readiness 正常。
2. 在文献库导入一篇 PDF，再按需演示 EPUB、DOCX、Markdown 或 TXT。逐篇查看处理状态；只有处理成功的版本会成为当前可读版本，失败文件不会替换旧版本。
3. 打开一篇文献，演示对应阅读方式：PDF 使用页码/目录/缩略图，EPUB 按章节及 CFI 位置，Markdown/TXT 按稳定段落锚点。DOCX 保留原件并展示转换后的 PDF；提醒观众 Word 与 LibreOffice 的分页和排版可能不同。
4. 在阅读器选择一段原文，通过“向 AI 提问”或“摘录到笔记”发送上下文。说明当前上下文会包括页面类型、文献版本、格式化位置及选区；切换页面只影响下一轮，不会改写正在运行的提问快照。
5. 打开全局助手，选择“全库”或指定文献范围，提出一个可核对的问题。查看回答依据和位置，再点引用返回原文。遇到模糊文献匹配时，从候选列表选择目标文献。
6. 打开独立阅读笔记，编辑标题与正文，演示自动保存、版本历史和样式设置。对助手给出的笔记修改候选，先查看当前内容与建议，再决定是否采纳；候选不会在确认前覆盖当前版本。可演示编辑期间的 revision 冲突会保留草稿。
7. 有正在运行的长任务时，可使用“停止”；停止请求之后等待服务端状态确认，查看已生成内容仍在会话历史中。切换到其他会话再返回，检查各会话草稿与历史分别保留。
8. 演示结束后执行 `docker compose --file compose.production.yaml down`。不要使用 `down -v`；该参数会删除数据库和原始文献数据卷。

旧专题与学习成果入口不再属于当前产品导航；升级前已有记录与版本仍保存在数据库中，旧专题/成果深链会转到文献库。演示时不要把这些历史数据误称为新建流程。

遇到引用不完整时，回到原文位置确认；证据不足时保留“不足以判断”的结论。不要将候选评测报告、自动提取文字或转换后的 DOCX 排版说成导师确认的学术结论或与 Word 完全一致的版面。
